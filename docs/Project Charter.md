# Creator Command Center — Project Charter

## Mission

Create a desktop Creator Command Center that makes streaming and social-content work easier to run, review, and improve from one trusted place.

## Vision

The app should feel like **Mission Control**: open it and immediately understand what happened, what matters next, and what action to take. It is a creator workspace, not a collection of disconnected dashboards.

## Product principles

1. **Actionable over ornamental.** Numbers should lead to a clear next action.
2. **One calm workspace.** Reduce browser-tab hopping and context switching.
3. **Automation with control.** Automate repetitive work; require approval for public-facing or irreversible actions.
4. **Local-first foundation.** Core functions should remain useful with low or no ongoing AI cost.
5. **Provider-flexible AI.** AI providers are replaceable integrations, never the product's only foundation.
6. **Private by default.** Credentials, content, and analytics remain under the owner's control.
7. **Grow by vertical slices.** Each sprint must leave a testable, useful product increment.

## Version 1 success criteria

- Start and end a streaming session from a focused streaming workflow.
- See recorded sessions and selected cross-platform growth metrics in one place.
- Review a post-stream briefing with duration, audience-growth changes, and next steps.
- Draft content and automation actions without requiring public publishing.
- Maintain a reliable activity log for every integration and automation action.

## Out of scope for version 1

- Roblox development, asset creation, or game-management tools.
- A full nonlinear video editor.
- Autonomous publishing, deleting, or financial actions.
- A multi-tenant SaaS product or creator marketplace.
- Complex predictive analytics before reliable data collection exists.

## Stakeholders and roles

| Role | Responsibility |
| --- | --- |
| Product owner | Sets priorities, approves public actions, tests each sprint. |
| Product/architecture assistant | Keeps documentation, flows, and build tasks clear. |
| Implementation assistant or developer | Builds scoped work from the sprint specifications. |
| Creator Command Center | Stores approved preferences, data, logs, and workflow state. |

## Decision rule

If a proposed feature does not save time, reduce context switching, or improve a creator decision, it does not belong in version 1.

## Current checkpoint

Foundation documents are established. The next checkpoint is Sprint 1: a polished local desktop shell with mock data and no required external accounts.
